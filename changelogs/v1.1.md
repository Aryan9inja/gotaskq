# v1.1 - Multi-Queue Support & Core Fixes

## Overview
Version 1.1 brings robust multi-queue support, resolves deadlocks in the memory queue, and introduces key configuration and architectural improvements. The worker pool has been refactored to round-robin across dynamically registered queues without blocking.

## Key Changes
### Multi-Queue Support
- **Dynamic Worker Pool:** Workers no longer block on a single queue. Instead, they poll across all registered queues in a round-robin manner.
- **Queue Registrar:** Introduced `queue.Registrar` interface. Queues created via the `POST /queue/{name}` API are now dynamically added to the worker pool and start processing immediately.
- **Retry Binding Fix:** The `RetryEngine` no longer stores a single default queue. It now routes failed jobs back to the specific queue they were executed from.
- **Queue Factory Integration:** Both in-memory and Redis backends use factories (`queue.Factory`) allowing dynamic queue instantiation.

### Deadlock Resolution
- Fixed a major deadlock bug within the memory queue's `Dequeue` method, ensuring workers correctly wait for and process jobs without halting the pool.

### TTL for Completed Jobs
- **`COMPLETE_JOB_TTL`:** Completed jobs are now retained for a configurable TTL window (default 5 minutes) rather than being deleted immediately, improving observability and queryability after execution.

### Benchmarks
Tested on **AMD Ryzen 5 5600H (12 Threads) with 16GB RAM**.
Stress testing with a multi-queue script (`3 queues x 50,000 jobs = 150,000 jobs total`):
- **In-Memory Backend:** Achieved an average throughput of ~25,600 req/sec per queue (~76,800 total req/sec) with an average latency of ~0.007 secs.
- **Redis Backend:** Achieved an average throughput of ~5,680 req/sec per queue (~17,040 total req/sec) with an average latency of ~0.035 secs.

*Note on performance difference:* The in-memory queue benefits from direct memory access without network boundary overhead, while Redis deals with socket communication, data serialization, and single-threaded data structure persistence which lowers raw throughput.
