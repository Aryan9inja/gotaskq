# v1.2 - Multi-Queue Support & Core Fixes

## Overview
Version 1.2 adds in memory DLQ support, it also intoduces embedded library support with all the in memory operations using copy of data to fix race conditions.

## Key Changes
### Multi-Queue Support
- **In memory dlq:** DLQ is now supported for in memory queue, failed jobs are moved to the dlq and can be retried or inspected later.
- **Embedded library support:** The library can now be embedded directly into applications, providing seamless integration with existing codebases. 
- **Race Condition Fixes:** All in-memory operations now use a copy of the data to fix race conditions, ensuring thread safety and data integrity when multiple workers are processing jobs concurrently.


### Benchmarks
Tested on **AMD Ryzen 5 5600H (12 Threads) with 16GB RAM**.
Stress testing with a multi-queue script (`3 queues x 50,000 jobs = 150,000 jobs total`):
- **In-Memory Backend:** Achieved an average throughput of ~25,600 req/sec per queue (~76,800 total req/sec) with an average latency of ~0.007 secs.
- **Redis Backend:** Achieved an average throughput of ~5,680 req/sec per queue (~17,040 total req/sec) with an average latency of ~0.035 secs.

*Note on performance difference:* The in-memory queue benefits from direct memory access without network boundary overhead, while Redis deals with socket communication, data serialization, and single-threaded data structure persistence which lowers raw throughput.
